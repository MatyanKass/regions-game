# Regions — механики

Спецификация правил, достаточная, чтобы написать игру заново на другом языке. Все числа
взяты из `src/sim/balance.gd`, порядок проверок — из `src/sim/game_state.gd`. Если
что-то здесь расходится с кодом, прав код.

## Суть

Клеточная стратегия на двоих в реальном времени. У каждого игрока государство из клеток.
На своих клетках строишь здания, здания дают ресурсы, за ресурсы забираешь чужие и ничьи
клетки. Побеждает тот, у кого противник остался без клеток; если время вышло — у кого
клеток больше.

## Главное правило: детерминизм

Оба устройства прогоняют одну и ту же симуляцию над одним и тем же потоком команд и
обязаны получить **побитово одинаковое** состояние. Из этого следует всё остальное:

- **Только целые числа.** Ни одного `f32`/`f64` в симуляции. Числа с плавающей точкой
  допустимы исключительно в отрисовке.
- **Никакого деления с потерей.** Любое деление должно быть точным либо целочисленным с
  одинаковым поведением на обеих сторонах (в Rust `i64` делит к нулю — это же делает и
  GDScript, но проверьте на отрицательных).
- **Порядок обхода фиксирован.** Нельзя итерировать `HashMap`. Всё, что перебирается в
  симуляции, — это `Vec` в определённом порядке.
- **Сортировка должна быть полным порядком.** Там, где сортируем (укомплектование
  заводов), ключ обязан быть уникальным, иначе нестабильная сортировка даст разные
  результаты.

## Единицы

| Что | Значение |
|---|---|
| `TICKS_PER_SECOND` | 20 |
| `UNIT` | 1000 |

Монеты и сила хранятся в **тысячных**. То, что игрок видит как «10 монет», внутри
`10 000`. Тысячные, а не сотые, потому что клетка приносит 0.02 монеты в секунду — это
одна тысячная за тик; в сотых пришлось бы округлять.

20 тиков в секунду, а не 10, потому что кулдауны захвата равны 0.25 и 0.40 секунды: при
10 Гц ни один не выражается целым числом тиков.

Все длительности в спецификации — в тиках.

## Генерация мира

Детерминированная: `(seed, settings)` → одна и та же карта, байт в байт.

### Генератор случайных чисел

Xorshift32, реализован вручную намеренно — чтобы точная последовательность лежала в
репозитории и не поменялась вместе с обновлением библиотеки.

```
state = seed & 0xFFFFFFFF; if state == 0 { state = 0x9E3779B9 }

next_u32():
    x = state
    x = (x ^ (x << 13)) & 0xFFFFFFFF
    x = x ^ (x >> 17)
    x = (x ^ (x << 5))  & 0xFFFFFFFF
    state = x
    return x

next_range(n): if n <= 1 { 0 } else { next_u32() % n }
```

### Суша и море

```
total = width * height
sea_percent = задан в настройках, иначе 5 + next_range(11)   // 5..15
sea_target  = total * sea_percent / 100                      // целочисленно
terrain = [LAND; total]
```

Море растёт «кляксами» — не шум с порогом, потому что рост кляксами позволяет попасть в
заданный процент **точно**:

```
blobs = 2 + next_range(3) + total / 800     // на большой карте клякс больше,
                                            // иначе выйдет один материк и один океан
frontier = []
placed = 0
for _ in 0..blobs:
    c = next_range(total)
    if terrain[c] == LAND { terrain[c] = SEA; placed += 1; frontier.push(c) }

while placed < sea_target:
    if frontier.is_empty():
        c = первая LAND-клетка при обходе от next_range(total) по кругу
        if нет такой { break }
        terrain[c] = SEA; placed += 1; frontier.push(c); continue
    pick = next_range(frontier.len())
    cell = frontier[pick]
    free = ортогональные соседи cell, где terrain == LAND
    if free.is_empty() { frontier.remove(pick); continue }   // remove по индексу
    target = free[next_range(free.len())]
    terrain[target] = SEA; placed += 1; frontier.push(target)
```

Порядок соседей везде один и тот же: **влево, вправо, вверх, вниз** (с проверкой границ,
края карты — стена, мир не заворачивается).

### Стартовые клетки

```
start_distance = max(16, min(width, height) * 40 / 100)
```

Один игрок (свободная игра) — центр карты. Двое — зеркально относительно центра, ось
выбирается сидом:

```
half = start_distance / 2
diag = start_distance * 3 / 8
match next_range(4):
    0 => [(-half, 0), (half, 0)]
    1 => [(0, -half), (0, half)]
    2 => [(-diag, -diag), (diag, diag)]
    _ => [(-diag, diag), (diag, -diag)]
```

Идеальная точка зажимается в границы карты, дальше — спираль наружу до первой свободной
клетки суши. Спираль обходится по возрастающему радиусу Чебышёва, внутри радиуса `dy`
внешним циклом, `dx` внутренним — это важно для повторяемости.

## Состояние мира

```rust
struct World {
    seed: i64,
    settings: Settings,          // размер, процент моря, режим, лимит матча
    width: usize, height: usize,

    terrain:     Vec<u8>,        // 0 = суша, 1 = море
    owner_of:    Vec<u8>,        // индекс игрока, 255 = ничья
    building_at: Vec<u8>,        // тип здания, 0 = пусто
    level_at:    Vec<u8>,        // 1..=5 где стоит здание, иначе 0

    coins: Vec<i64>,             // в тысячных
    power: Vec<i64>,
    alive: Vec<bool>,
    capture_ready: Vec<i64>,     // тик, с которого игроку снова можно захватывать

    ships: Vec<Ship>,
    sites: Vec<Site>,            // стройки в процессе

    tick_count: i64,
    finished: bool,
    winner: i32,                 // -1 = ничья или ещё идёт
}

struct Site { cell: usize, owner: u8, kind: u8, started: i64, ready: i64 }
struct Ship { owner: u8, port: usize, target: usize, path: Vec<usize>, step: usize, ticks: i64 }
```

Сетка — плоские массивы, индекс `cell = x + y * width`.

## Здания

| Здание | Стройка, с | Монеты | Сила | Люди | Даёт (за уровень) | Уровни |
|---|---|---|---|---|---|---|
| Дом | 5 | 30 | — | — | +2 жителя | 5 |
| Барьер | 6 | 50 | 20 | — | ничего (см. захват) | **1** |
| Казарма | 8 | 40 | 25 | — | +10 к лимиту силы | 5 |
| Завод | 9 | 40 | — | **занимает 1** | +0.2 монеты/с | 5 |
| Военная база | 12 | 60 | 15 | — | +1 сила/с | 5 |
| Банк | 13 | 80 | — | — | +10 к лимиту монет | 5 |
| Порт | 15 | 60 | 30 | — | корабли, только у моря | 5 |

Во внутренних единицах: завод `coin_per_tick = 10`, военная база `power_per_tick = 50`,
банк `coin_cap = 10 * UNIT`, казарма `power_cap = 10 * UNIT`, дом `people = 2`.

**Уровень умножает эффект, но не число рабочих.** Завод 3 уровня приносит втрое больше и
занимает того же одного человека — поэтому улучшение это ответ на «земля кончилась».

**Цена уровня N = базовая цена × N.** То есть здание 3 уровня суммарно стоило
`1 + 2 + 3 = 6` базовых цен, а даёт втрое. Улучшение экономит место, но никогда не даёт
скидку.

```
upgrade_cost(kind, to_level) = base_cost(kind) * to_level
invested(kind, level)        = base_cost(kind) * level * (level + 1) / 2
```

## Экономика

### Базовый доход

Пока у игрока есть **хотя бы одна клетка**:

```
coin_per_tick += 50      // 1 монета/с
power_per_tick += 50     // 1 сила/с
```

Это то, что не даёт игроку с одной клеткой выпасть из игры.

### Земля

Каждая клетка даёт:

```
coin_per_tick += 1                  // 0.02 монеты/с
coin_cap      += UNIT / 2           // +0.5 монеты вместимости
power_cap     += UNIT / 4           // +0.25 силы вместимости
```

Мало на клетку, заметно на сотне. Без этого страна из 500 клеток приносила ровно
столько же, сколько из 20, и вторая половина партии превращалась в закрашивание пустоты.

### Лимиты

```
coin_cap  = 100 * UNIT + сумма(coin_cap зданий × уровень) + клетки * UNIT/2
power_cap =  50 * UNIT + сумма(power_cap зданий × уровень) + клетки * UNIT/4
```

Доход выше лимита **теряется**, а не копится.

### Люди и укомплектование заводов

Дома дают вместимость, заводы занимают по человеку. Жильё можно потерять — захват дома
уносит его жителей, — поэтому заводов может стать больше, чем людей. Тогда лишние
**стоят и не приносят ничего**:

```
jobs = все клетки игрока со зданием, у которого workers > 0
jobs.sort_by(|a, b| (b.level, a.cell).cmp(&(a.level, b.cell)))
     // уровень по убыванию, при равенстве — индекс клетки по возрастанию

spare = people
for job in jobs:
    if spare < job.workers { idle.push(job.cell); continue }
    spare -= job.workers
    coin_per_tick += coin_per_tick(job.kind) * job.level

free_people = spare      // никогда не отрицательное
```

Сначала укомплектовываются самые крупные заводы — так поступил бы и человек. Тай-брейк по
индексу клетки обязателен: без него две стороны насчитают разный доход.

## Команды

Команды применяются **до** тика, в том порядке, в котором их выстроил хост. Каждая либо
успешна, либо возвращает код причины. Порядок проверок важен: игрок видит именно первую
сработавшую причину.

### BUILD(cell, kind)

1. `cell` в границах → `bad_cell`
2. `kind` существует → `bad_building`
3. клетка принадлежит игроку → `not_your_cell`
4. клетка — суша → `sea_cell`
5. на клетке нет здания **и нет стройки** → `cell_occupied`
6. если здание прибрежное — клетка касается моря → `needs_coast`
7. хватает монет → `not_enough_coins`
8. хватает силы → `not_enough_power`
9. если нужны рабочие: `free_people - promised_workers >= workers` → `not_enough_people`

Успех: списать стоимость, создать стройку
`Site { cell, owner, kind, started: tick, ready: tick + build_seconds * 20 }`.
Здание **не появляется на сетке** — клетка занята стройкой и ничего не даёт.

`promised_workers(player)` — сумма `workers` всех строек этого игрока. Без этого один дом
позволял бы заказать десять заводов сразу.

### UPGRADE(cell)

Мгновенно, стройка времени не занимает.

1. границы → `bad_cell`
2. владелец → `not_your_cell`
3. здание есть → `nothing_to_upgrade`
4. `level + 1 <= max_level` → `max_level`
5. монеты → `not_enough_coins`
6. сила → `not_enough_power`

Успех: списать `upgrade_cost(kind, level+1)`, `level += 1`.

### DEMOLISH(cell)

1. границы, 2. владелец.
3. **Если на клетке стройка** — вернуть монеты и силу целиком, убрать стройку, зажать по
   лимиту, закончить. Ничего же ещё не построено.
4. здание есть → `nothing_to_demolish`
5. Иначе: посчитать `invested`, убрать здание (и корабли этого порта), начислить
   `invested * 50 / 100`, зажать по лимиту.

Возврат начисляется **после** удаления здания: снос банка уменьшает лимит, и возврат
зажимается уже новым лимитом.

### CAPTURE(cell)

1. границы → `bad_cell`
2. суша → `sea_cell`
3. клетка не моя → `already_yours`
4. клетка ортогонально граничит с моей → `not_adjacent`
5. `tick_count >= capture_ready[player]` → `on_cooldown`
6. `power >= 10 * UNIT` → `not_enough_power`

Успех:

```
power -= 10 * UNIT
defended = владелец клетки != NEUTRAL      // считается ДО захвата
barrier  = на клетке стоял барьер          // тоже ДО
take_cell(player, cell)
cooldown = if defended { 8 } else { 5 }    // 0.40 с / 0.25 с
if barrier { cooldown = max(cooldown, 80) }   // 4 секунды
capture_ready[player] = tick_count + cooldown
```

Обороны как таковой нет: захват всегда удаётся. Барьер клетку не спасает — он
останавливает наступление, которое через неё шло.

### LAUNCH_SHIP(port_cell, target)

1. обе клетки в границах → `bad_cell`
2. `port_cell` моя и на ней порт → `no_port`
3. `target` не моя → `already_yours`
4. `target` — суша → `sea_cell`
5. у этого порта нет корабля в пути → `port_busy`
6. `power >= 10 * UNIT` → `not_enough_power`
7. `sea_path(port_cell, target)` не пуст → `no_sea_route`

Успех: списать 10 силы, добавить корабль со `step = 0`, `ticks = 0`.

### take_cell(player, cell) — общая часть захвата и высадки

```
previous = owner_of[cell]
если на клетке порт — убрать его корабли
убрать стройку на клетке (работа брошена)
building_at[cell] = 0; level_at[cell] = 0    // всё, что стояло, сравнивается с землёй
owner_of[cell] = player
если previous != NEUTRAL:
    зажать ресурсы previous по его новым лимитам
    если у previous не осталось клеток — он выбыл
проверить конец матча
```

## Корабли

Порт строится только на клетке, касающейся моря. Отправка стоит 10 силы. Один порт ведёт
один корабль за раз.

**Маршрут — поиск в ширину по морю**, а не прямая:

```
sea_path(from, to):
    если from == to или to не суша → пусто
    BFS от from
    соседи обходятся в фиксированном порядке (влево, вправо, вверх, вниз)
    в очередь попадают только клетки моря
    цель засчитывается, только если пришли в неё НЕ из from
        (то есть корабль обязан пересечь хотя бы одну клетку воды)
    путь = клетки от from (не включая) до to (включая)
```

Фиксированный порядок соседей делает кратчайший путь **единственным определённым
ответом** — иначе две стороны выбрали бы разные пути одинаковой длины и разошлись.

Движение, каждый тик:

```
ticks += 1
если ticks < 60 → всё                       // 3 секунды на клетку
ticks = 0; step += 1
если step < path.len() → всё
// прибыл
если владелец жив, target суша и не его → take_cell(владелец, target)
корабль убирается
```

`reachable_shores(port)` — один BFS по морю от порта, возвращает все клетки суши,
касающиеся достижимой воды. Интерфейс подсвечивает именно это, так что подсвеченное и
разрешённое не могут разойтись.

## Порядок тика

Порядок критичен: он наблюдаем и обе стороны обязаны его повторять.

```
tick():
    если finished → выход
    1. двигать корабли (высадка может захватить клетку)
    2. начислить доход всем живым, зажать по лимитам
    3. tick_count += 1
    4. завершить стройки, у которых ready <= tick_count
       (стройка бросается, если клетка сменила владельца или уже застроена)
    5. проверить конец матча
```

Стройки обрабатываются **после** инкремента счётчика — чтобы «заказал здание на 9 секунд
и подождал 9 секунд» давало здание, а не «ещё один тик».

## Конец матча

- **Свободная игра не кончается никогда** — ни выбывания, ни таймера.
- Живых игроков `<= 1` → конец, победитель — оставшийся (или `-1`, если не осталось
  никого).
- Иначе, если лимит задан и `tick_count >= limit` → побеждает тот, у кого больше клеток;
  при равенстве — ничья (`-1`).

## Сеть: лок-степ

Хост — единственный владелец часов.

```
хост, каждый тик:
    собрать команды, накопившиеся с прошлого тика (свои и присланные)
    применить их по порядку
    tick()
    разослать (tick_count, команды)
    запомнить хеш состояния

клиент:
    своих часов нет; шагает только когда пришла пачка команд
    применяет те же команды в том же порядке, затем tick()
    раз в 50 тиков шлёт хосту (tick, хеш)

хост при несовпадении хеша:
    шлёт снимок состояния целиком; клиент заменяет им своё
```

Команда клиента **не применяется у него локально сразу** — она уходит хосту и приходит
обратно в пачке. В локальной сети это единицы миллисекунд, и это полностью снимает
необходимость в откате.

Команды кодируются четвёркой целых: `[player, kind, a, b]`.

### Хеш состояния

Полный обход сетки на каждый хеш неприемлем на большой карте, поэтому поддерживается
накопительная контрольная сумма, которая обновляется при каждом изменении клетки:

```
signature(cell) = (owner*131 + building*17 + level*7 + 1) * (cell + 1)
```

При любом изменении: вычесть старую сигнатуру, поменять клетку, прибавить новую.
Умножение на индекс нужно, чтобы обмен содержимым двух клеток менял сумму — простая
сумма этого бы не заметила.

Итоговый хеш — FNV-1a по: `tick_count`, `seed`, контрольной сумме сетки, по каждому
игроку `coins/power/alive/capture_ready`, по стройкам `cell/kind/ready`, по кораблям
`owner/port/target/step/ticks`.

## Производительность: то, без чего большие карты не работают

Карта может быть 1000×1000 = миллион клеток. Наивная реализация умирает в двух местах.

**1. Доход нельзя считать обходом сетки.** Держите бегущие итоги на игрока и обновляйте
их в тех немногих местах, что меняют клетку:

```
cells, people, coin_rate (от зданий без рабочих), power_rate,
coin_cap, power_cap (от зданий), jobs: Vec<cell>
```

Всякое изменение клетки — `forget(cell)` → изменить → `remember(cell)`, где эти две
функции прибавляют и вычитают вклад клетки. Третьего способа трогать сетку быть не
должно.

Обязательно напишите функцию честного пересчёта и тест, который после **каждого** вида
изменения сверяет кэш с ней. Разъехавшийся кэш не упадёт — он тихо заплатит одному игроку
неправильный доход, и стороны разойдутся.

**2. Рисовать надо только видимое окно.** Считайте прямоугольник клеток, попадающих в
камеру, и обходите его, а не всю карту.

Замеры на текущей реализации (GDScript, не Rust): мир 400×400 генерируется за 180 мс и
проходит 200 тиков за 3 мс; миллион клеток строится за 1.6 с.

## Грабли, на которые я наступил

Стоит прочитать до того, как наступите сами.

1. **Свободные люди уходили в минус.** Завод занимает жителя навсегда, но жильё можно
   отобрать. Заводы продолжали числиться работающими и печатать монеты из ниоткуда.
   Отсюда правило укомплектования выше.
2. **0.25 секунды не выражается в тиках при 10 Гц.** Кулдаун потребовал 20 Гц.
3. **0.02 монеты в секунду не выражается в сотых.** Доход с земли потребовал тысячных.
4. **Стройка завершалась на тик позже ожидаемого**, пока обработка стояла до инкремента
   счётчика.
5. **Бот принимал стройплощадку за пустую клетку** и заказывал туда снова и снова. Всё,
   что смотрит на «пустые клетки», обязано учитывать стройки.
6. **Захват здания освобождает рабочего** — не забудьте пересчитать людей у пострадавшей
   стороны, а не только у захватчика.
7. **Возврат при сносе надо зажимать по лимиту**, который уже уменьшился: снос банка
   иначе оставляет игрока выше потолка.
8. **Прямая линия для корабля — плохая идея.** Изогнутый залив блокировал очевидно
   возможную высадку; нужен BFS.

## Что я бы сделал иначе на Rust

- `i64` для монет и силы, `u8` для владельца, здания и уровня, `Vec<u8>` для сеток.
- Симуляция — отдельный крейт без зависимостей от движка и без ввода-вывода. Тогда её
  можно гонять тестами в тысячи тиков за миллисекунды, что и есть главный инструмент.
- Команды — `enum` с явными вариантами, результат — `Result<(), Refusal>`, где `Refusal`
  тоже `enum`. Строковые коды причин в текущей реализации — уступка динамическому языку.
- Снимок состояния — то же самое, что сохранение и что ответ рассинхронившемуся клиенту.
  Одно определение «всего состояния», а не три.
- Тесты, которые окупились больше всех: детерминизм (два состояния под одним потоком
  команд обязаны совпадать по хешу каждый тик) и сверка кэша с честным пересчётом.
